# What `bun test` supports for this repo

Date: 2026-10-03 · Bun 1.4.1 · Used by: T-001, `docs/tests.md`

## Method

Throwaway test files with `bunfig.toml` and a preload, run with `bun test`.

## Results

| Check | Result |
| --- | --- |
| Legacy decorators (`experimentalDecorators` in `tsconfig.json`) | work |
| `jest.useFakeTimers()` + `jest.advanceTimersByTime()` from `bun:test` | work |
| `?raw` import through a `Bun.plugin` in the preload | works |
| Globals `fetch`, `Response`, `addEventListener` | present |
| `Bun.YAML.parse` | present |
| `jest.isolateModules`, `jest.resetModules` | absent |
| Dynamic import with a query string (`./x.ts?a`, `./x.ts?b`) | gives separate module instances, but not of their imports |
| `new Response("", { status: 204 })` | accepted (browsers and Node throw) |

## Consequences

- Route and message registration must be explicit (`createRouter`, `bindMessages`, `bootstrapWorker(scope)`) so tests build fresh instances.
- Page-hook tests assert identity and `bodyUsed`, not constructor errors.

## 2026-10-04: package scripts and happy-dom

Found while doing T-001 and T-002.

- `bun run <script>` puts `node_modules/.bin` first on `PATH`. The `bun` npm package in `dependencies` (`^1.0.25`, resolved to 1.1.20) put an old `bun` binary there, so `bun run test` ran Bun 1.1.20 while `bun test` ran 1.4.1. Under 1.1.20 the `?raw` plugin and the fake-timer test failed. The dependency now pins `^1.4.1`; T-701 removes it once the release workflow installs Bun itself (T-702). Check with `bun run test`: its first line prints the Bun version.
- happy-dom 20.14 calls `on*` handler properties without binding `this` to the element (browsers do). `content-script.js` uses `this.remove()` in `onload`; its test calls `onload` with the element as `this`.
- With `disableJavaScriptFileLoading`, a `<script src>` added by the code under test fires `error` and happy-dom reports a `NotSupportedError` on `console.error`; nothing is fetched.
- `GlobalRegistrator.register` copies every window property onto `globalThis` (`fetch`, `Response`, `URL`, `EventTarget`, ...) and `unregister` restores them. Keys happy-dom does not define (`Worker`, `chrome`, `request`) are restored by `usePageEnv`.
- `bun test --randomize` (5 seeds) passes: no test depends on file order.
